# Threat register

All entries are **MODELED THREATS**, not discovered vulnerabilities. Control evidence is tracked separately in PROJECT_STATUS.md; implemented tests do not validate every residual-risk scenario.

| ID / STRIDE | Asset | Threat actor | Entry point / trust boundary | Scenario | Required control | Detection | Verification | Residual risk |
|---|---|---|---|---|---|---|---|---|
| `T-AUTH-001` S/D | Identity, availability | Anonymous attacker | Login / `TB-01` | Guessing or response differences obtain/enumerate an account or exhaust login | Generic response, password verifier, throttling | Repeated failure/rate events | `VER-AUTH-001`, `VER-RATE-001` | Distributed low-and-slow attempts |
| `T-RESET-001` S/E | Identity | Anonymous attacker/token thief | Reset / `TB-01`,`TB-02` | Predictable, leaked, old, or reusable reset token takes over account | Random opaque digest-stored token, expiry, one use, generic response | Reset misuse events without token | `VER-RESET-001`,`VER-LOG-002` | Compromised email/device |
| `T-AUTHZ-001` T/I/E | Ownership/domain data | Authenticated user B | Resource ID / `TB-01`,`TB-02` | User B reads or mutates user A's property/invoice | Deny-by-default object policy using server ownership | Correlated denial event | `VER-AUTHZ-001` with pre/post state | Untested policy state or race |
| `T-AUTHZ-002` E | Admin authority | Ordinary user | Admin endpoint / `TB-01` | UI hiding or JWT presence substitutes for function authorization | Explicit admin policy | Admin denial event | `VER-AUTHZ-002` | Legitimate privileged abuse |
| `T-INPUT-001` T/E | Role/ownership/domain | Authenticated user | JSON DTO / `TB-01` | `role`, `ownerId`, `isVerified`, or nested unknown field changes protected state | Typed DTO + reject unknown + server allowlist | Validation/protected-field event | `VER-INPUT-001`,`VER-MASS-001` | Valid but harmful combinations |
| `T-WEBHOOK-001` S/T/R | Invoice/event state | Anonymous sender/replayer | Webhook / `TB-03` | Invalid, old, changed, duplicate, unordered, or misbound signed event creates wrong effect | Raw signature, age, idempotency, state and amount binding | Signature/replay/transition event | `VER-WEBHOOK-001` | Provider key compromise/concurrency |
| `T-UPLOAD-001` T/E/D | Files/availability | Uploader | Multipart / `TB-01`,`TB-02` | Type confusion, traversal, or excessive file reaches unsafe storage | Independent size, extension, MIME, magic, name, storage, header controls | Bounded rejection reason | `VER-UPLOAD-001` | Valid malicious content/parser zero-day |
| `T-XML-001` I/E/D | Data/availability | Import submitter | XML / `TB-01`,`TB-03` | Entity/DTD/depth/expansion causes file/network access or exhaustion | Reject DTD/entities, no resolver, bounded bytes/depth/nodes | Parser policy event | `VER-XML-001` | Parser defects |
| `T-SSRF-001` I/E | Secrets/network | URL controller | URL policy / `TB-03` | Scheme, IP, DNS or redirect trick reaches private/metadata target | Canonical allowlist + no redirects + timeout/byte budget | Destination-category denial | `VER-SSRF-001` | Allowlisted host compromise/DNS rebinding |
| `T-AI-001` T/I/E/D | AI boundary/data/quota | Prompt author/model output | AI parse / `TB-01`,`TB-03` | Injection/output invokes tool or URL, leaks data, or exhausts quota | Mock, minimization, schema, allowlists, quota | Tool/schema/quota event | `VER-AI-001` | Semantic injection remains |
| `T-LOG-001` R/I/T | Evidence/secrets | Input author/log reader | Event sink / `TB-02` | Missing events impede investigation or sensitive fields leak/inject logs | Structured encoding, redaction, correlation | Redaction and sink health tests | `VER-LOG-001`,`VER-LOG-002` | New uninstrumented paths |
| `T-SECRET-001` I/E | Secrets/source | Repo reader/build step | Config / `TB-04` | Credential is committed/printed or placeholder accepted in production | Env schema, production refusal, Gitleaks | Scanner and startup failure | `VER-SECRET-001` | Secrets outside Git |
| `T-CI-001` T/E/R | Source/credentials/artifact | PR author/compromised action | Workflow / `TB-04` | Untrusted input executes with broad token; floating action changes | Minimal permissions, SHA pins, event isolation, no interpolation | Workflow policy/actionlint | `VER-CI-001` | Platform/maintainer compromise |
| `T-SUPPLY-001` T/E | Dependencies/artifact | Compromised package source | Build / `TB-04`,`TB-05` | Unlocked or malicious component enters artifact | Locks, trusted registry, SCA, SBOM | Normalized scan + lock drift | `VER-SUPPLY-001` | Unknown malicious package |
| `T-REGISTRY-001` S/T/R | Release artifact | Registry attacker | Push/pull / `TB-05`,`TB-06` | Mutable/substituted image is deployed | Digest, provenance, attestation, scoped publisher | Digest/identity mismatch | `VER-ARTIFACT-001` | Signing identity/control-plane compromise |
| `T-K8S-001` E/T | Cluster/secrets | Compromised pod | Runtime/RBAC / `TB-06` | Root, capabilities, token or wildcard RBAC enables pivot | Hardened context, no token, narrow RBAC | IaC/admission/runtime audit | `VER-K8S-001` | Kernel/runtime vulnerability |
| `T-K8S-002` I/E/D | Cluster/data/availability | Network actor/peer pod | Ingress/network / `TB-06` | Public admin plane, open east-west network or missing limits expands blast radius | Controlled ingress, default-deny policy, resources, namespaces | IaC/network audit | `VER-K8S-002` | CNI/cloud-specific behavior |

STRIDE abbreviations: `S` spoofing, `T` tampering, `R` repudiation, `I` information disclosure, `D` denial of service, `E` elevation of privilege.
